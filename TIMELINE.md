## 2026-09-13 (Day 5)
- Started: M5 Gymnasium Environment (`atar/env/atar_env.py`,
  `tests/env/test_atar_env.py`).
- Finished: M5 fully complete — **20/20 tests pass in 129.42s** (venv/bin/python3 -m pytest).
- Issues hit:
  1. First test run: `test_efficiency_tool_call_cost` failed with
     `TypeError: '<=' not supported between instances of 'float' and 'ApproxScalar'`
     — `pytest.approx()` doesn't support `<=` operator. Fixed by using direct
     float comparison (`rc.efficiency <= -0.5 + 1e-6`).
  2. First test run: `test_check_env_passes` failed because
     `check_step_determinism()` asserted that two identical-seed step() calls
     produce the same observation — impossible with a non-deterministic LLM
     sampler + BM25 20% noise. Fixed by registering `ATAREnv` with
     `gymnasium.register("ATAR-v0", nondeterministic=True)` and setting
     `env.spec = gym.spec("ATAR-v0")` in the test so the determinism check
     is correctly skipped.
  3. Second test run: `test_check_env_passes` failed on 3 gymnasium warnings
     (`warn=...` parameter deprecated in gymnasium 1.3.0, Box bounds -inf/inf
     soft warning). Fixed by removing the deprecated `warn=True` kwarg and
     filtering known benign warnings (Box bounds are correct — semantic
     embeddings have unbounded range by design).
  4. `State` was not a defined type in `shared_types.py` (only `STATE_DIM`
     and range constants exist). Removed stale `State` from imports.
- Blocked: none

## 2026-09-13 — M3 Batch Extension + M7 RL Policy & Training

### M3 Batch Extension
- Started: Added `encode_batch()` and `generate_batch()` to `LLMInterface`.
- Finished: 11/11 M3 tests pass (6 original + 5 batch tests).
- Issues hit & resolved:
  1. `test_encode_batch_matches_single_smoke` initially failed with device mismatch
     (`cuda:0` vs `cpu`) — root cause was that `encode()` was missing `.cpu()` at
     return despite the comment saying "Return on CPU". Fixed by adding `.cpu()`.
  2. Investigation into `encode_batch` vs `encode` discrepancy:
     - Checked tokenizer: `padding_side = 'left'` is correct for decoder-only LLMs.
     - Confirmed masked mean-pooling correctly ignores padding positions in `encode_batch`.
     - In an identical, non-padded batch of 3 on CPU, `max_diff` was ~0.086 and cosine similarity was 0.99994, confirming the discrepancy stems from floating-point reduction and multi-threaded CPU BLAS operation ordering across batch sizes (with left-padding adding minor rounding variance). Added note that magnitude under 4-bit BnB quantization on Kaggle T4 must be re-verified.
     - Confirmed `encode_batch` executes exactly one forward pass for N inputs.
     - Added `test_encode_batch_no_padding_tighter_tolerance` and `test_encode_batch_single_forward_pass_count`. All 11 tests pass.
